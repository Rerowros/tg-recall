# Журнал изменений

## v0.8.1 - 2026-10-03

### Исправлено

- `stats(query=…)` учитывает и голосовые, чья расшифровка совпала с запросом, каждое сообщение один раз, как `search`.
- `transcribe` использует локальную программу распознавания речи по пути из `transcription.executable`, а не только найденную в `PATH`. Проверено вживую с Faster-Whisper-XXL на видеокарте: два голосовых скачаны и расшифрованы примерно за 20 секунд.
- `sync` из оболочки AI-агента (CLI, не MCP) по умолчанию работает 90 секунд вместо часа, чтобы среда агента не обрывала команду; следующий вызов продолжает. В терминале владельца остаётся 3600 секунд.
- `tg-recall stats` больше не предлагает неиспользуемый параметр `--budget`.

### Добавлено

- `scripts/agent_bench.py`: прогоняет ваши вопросы через настоящего агента (Claude Code без интерфейса, только с инструментами tg-recall) и записывает число ходов, вызовы инструментов, токены их ответов, общие токены, стоимость, время и проверку ключевых слов; `--compare` показывает разницу между двумя прогонами. Вопросы и результаты лежат в профиле, потому что в них названия ваших чатов; формат — в `scripts/bench_questions.example.json`.

## v0.8.0 - 2026-10-03

Агенты теперь дёшево работают с большими периодами: `stats` считает вместо чтения, `export` пишет весь период в файл, а `sync` больше не блокирует агента. Владелец видит, как агенты пользуются архивом, через `tg-recall usage`.

### Как обновиться

- Обновление: `uv tool install --force https://github.com/Rerowros/tg-recall/releases/download/v0.8.0/tg_recall-0.8.0-py3-none-any.whl`.
- Значение по умолчанию `ai_access.sync_max_seconds` изменилось с `50` на `20`: теперь это время, которое ждёт один вызов MCP `sync`, прежде чем скачивание продолжится в фоне. Конфиг, сохранённый прошлой версией, сохраняет своё значение; чтобы перейти на новое, выполните `tg-recall config set ai_access.sync_max_seconds 20`.
- `transcribe` выключен, пока владелец не задаст `ai_access.allow_transcribe` равным `true`. `export` для агентов включён по умолчанию (до `50000` сообщений в файле); `tg-recall config set ai_access.max_export_messages 0` его убирает.

### Добавлено

- MCP `stats(chats, since, until, from, media, query, by)` и `tg-recall stats [--query] [--by day|week|month]` с обычными флагами области: число сообщений по дням, неделям или месяцам (с `query` — совпадения за каждый период), самые активные авторы, темы форума и чаты. Несколько сотен токенов вместо чтения тысяч сообщений.
- MCP `export(chats, since, until, from, media)`: записывает весь период или тему целиком в однострочном формате `read` с датой в каждой строке в файл в каталоге `exports` профиля. Возвращает путь, число строк, оценку токенов и подсказку, какими кусками читать; файл агенты читают своими инструментами для файлов. Ограничен `ai_access.max_export_messages` (по умолчанию `50000`; `0` убирает инструмент). CLI: `tg-recall export --chat ID[/TOPIC] --format text` (владелец может указать `--output`).
- MCP `transcribe(refs)` для до 5 ссылок `tg://`, только при `ai_access.allow_transcribe=true` (по умолчанию `false`): скачивает из Telegram указанные голосовые, аудио или видео и расшифровывает настроенным локальным провайдером `transcription.*`, если он доступен, а иначе встроенной расшифровкой Telegram (нужен Telegram Premium). Возвращает текст; расшифровки потом находятся поиском.
- Журнал использования: каждый вызов MCP и каждый вызов инструмента CLI из оболочки агента записывается строкой audit `agent_call` с инструментом, клиентом, аргументами (запрос, чаты, даты, лимиты; текста сообщений — никогда), токенами ответа, временем и кодом ошибки. `tg-recall usage [--since 7d] [--client NAME]` (только для владельца) показывает по каждому инструменту вызовы, ошибки, пустые ответы, средние и максимальные токены и среднее время, а ещё коды ошибок, пустые поиски, одинаковые вызовы в пределах 120 с, повторные поиски после пустого ответа и страницы `read` по 100+ сообщений.
- `ai_access.sync_background_minutes` (по умолчанию `30`), `ai_access.max_export_messages` (по умолчанию `50000`) и `ai_access.allow_transcribe` (по умолчанию `false`).

### Изменено

- MCP `sync` больше не блокирует: вызов ждёт `ai_access.sync_max_seconds` (теперь по умолчанию `20`, было `50`), потом скачивание продолжается в фоне в процессе MCP-сервера (лимит `ai_access.sync_background_minutes`) и показывает прогресс, сколько сообщений в чате или теме по данным Telegram и сколько примерно осталось. Пока оно идёт, `search` и `read` добавляют пометку и не запускают автообновление. `sync()` без аргументов показывает текущее или последнее скачивание (последнее — в течение 10 минут), иначе обновляет все разрешённые чаты. Одновременно идёт только одно скачивание. `sync` в CLI по-прежнему ждёт завершения и пишет прогресс в stderr.
- Синтаксис запроса `search`: слова (сначала все, потом любое), варианты `a | b` (синонимы, другие языки), `"exact phrase"` и `-word` для исключения. `stats` с `query` считает сообщения, которые подходят под запрос (все слова, без запасного поиска по любому слову).
- Инструкции MCP при initialize советуют агентам `stats` и `export` для больших периодов и объясняют фоновый `sync`.

### Исправлено

- Ссылка на чат и тему вида `Acme/157` больше не выбирает заодно одноимённый чат без этой темы (например, канал проекта рядом с его форумом).
- Сообщения форумов, скачанные до 0.7, получают свою тему при следующем запуске: ответ на корень темы становится принадлежностью к теме, сообщение без ответа попадает в General, ответы наследуют тему родителя. На реальном архиве так размечено 43,8 тыс. из 46 тыс. строк; строки, чей родитель не скачан, остаются без темы.
- `export` выгружает тему форума (`--chat <chat>/<topic>`, `t.me/c/<id>/<topic>` или `--topic`), добавляет в строки `topic_id` и `topic_title` и больше не обрезает молча на 100 000 сообщений; с `--limit` сообщает `truncated`.
- Долгий `sync` каждые 10 секунд пишет прогресс в stderr, чтобы было видно, что он работает.

## v0.7.0 - 2026-10-03

tg-recall теперь — небольшое ядро: локальный архив Telegram плюс `search`, `read`, `chats` и `sync` для вас и ваших AI-агентов через MCP или CLI. Всё, что вызывающий агент делает лучше сам, удалено. Это несовместимый релиз.

### Как обновиться

- Сначала сделайте backup: `tg-recall backup create --mode essential --output D:\Backups\tg-recall-before-0.7.zip`.
- При первом запуске архив мигрирует: `semantic_index`, таблицы эмбеддингов и sync scopes удаляются; таблицы wiki и research удаляются, только если они пустые; затем файл сжимается (`VACUUM`), если освободилось много места. Чаты, сообщения, медиа и транскрипты сохраняются.
- MCP-клиенты теперь получают `search`, `read` и `chats` (плюс `sync` при `ai_access.allow_sync=true`) вместо `list_allowed_chats`, `list_scopes`, `search_messages`, `get_message_context`, `ask_archive` и `retrieve_evidence`. Команда сервера по-прежнему `tg-recall-mcp`.
- Scopes больше нет: вместо `scopes create` с `sync run` / `sync ensure` используйте `tg-recall sync <chat> --since <date>`, а чаты, доступные агентам, перечислите в `ai_access.allowed_chat_ids` (или включите `ai_access.allow_all_chats`).
- Старые конфиги по-прежнему загружаются; ключи удалённых функций (`llm`, `semantic`, `provider_policy`, `ai_access.mcp_research_tools`) игнорируются.
- Обновление: `uv tool install --force https://github.com/Rerowros/tg-recall/releases/download/v0.7.0/tg_recall-0.7.0-py3-none-any.whl` (самообновления `tg-recall update` больше нет).

### Удалено

- `ask` и `retrieve`, ответы LLM внутри инструмента и провайдер OpenAI Responses.
- Семантический и гибридный поиск и эмбеддинги (локальный sentence-transformers, OpenRouter): `config embeddings`, `index embeddings` и `semantic_index` на каждое сообщение. Поиск — локальный полнотекстовый (SQLite FTS5).
- Research sessions, evidence sets и knowledge catalog вместе с их MCP-инструментами.
- Wiki memory; backup больше не включает папку wiki.
- Export packs (`pack`).
- Установщики harness `integrate`, `agent guide`, роутинг моделей Codex и setup prompt без версии.
- Самообновление `update`.
- `migrate legacy`, алиасы `tg-ecosystem` / `tg-ecosystem-mcp` и `TG_ECOSYSTEM_HOME`.
- Sync scopes (`scopes`, `sync run`, `sync ensure`) и лимит в 1000 сообщений за запуск.
- Extras `local-embeddings` и `openai-responses`, секции конфига `llm`, `semantic` и `provider_policy` и ключ `ai_access.mcp_research_tools`.

### Добавлено

- Компактные `search`, `read` и `chats` для MCP и CLI: одна строка на сообщение, в пределах бюджета токенов; `>` отмечает совпадение, `↩N` — ответ, строка `cite:` перечисляет ссылки `tg://`. `read()` без аргументов возвращает новое с прошлого чтения этим клиентом (первый вызов — последние 24 часа), поровну на каждый чат. С `--json` CLI возвращает `{"text", "count", "chat_ids"}`. Владелец в своём терминале видит все чаты архива; внутри оболочки AI-агента действуют только чаты из `ai_access`.
- Темы форума: выбираются ссылкой t.me (`t.me/<username>/<topic>`, `t.me/c/<id>/<topic>`) или `<chat>/<topic>`; `chats` показывает темы, у каждого сообщения сохраняются тема и её название.
- `tg-recall sync [TARGET...] [--since] [--max-seconds] [--media]`: обновляет чаты или темы форума через одно подключение к Telegram. Чат, который ни разу не синхронизировался, начинается с 30 дней назад, `--since` докачивает и более старую историю, а тема скачивается отдельно, а не вся группа. Прерывание безопасно, запись идёт пачками; FloodWait сохраняется и учитывается; `--media` ставит медиа в очередь на скачивание. Без целей обновляет allowlist или все чаты с сообщениями.
- Lock-файл на каждую Telegram-сессию: второй процесс сразу получает `busy`, а не ждёт.
- MCP-инструмент `sync` (только при `ai_access.allow_sync=true`): только читает Telegram, не выходит за allowlist и даты политики, ограничен по времени `sync_max_seconds` (`50`) и продолжается при следующем вызове. При `allow_sync` агентские `search` и `read` сначала подтягивают новые сообщения для чатов, синхронизированных больше `auto_refresh_minutes` (`10`) назад; ошибки (сессия занята, лимит Telegram) только добавляют пометку.
- Ключи `ai_access`: `allow_all_chats` (разрешены все чаты архива), `max_read_messages` (`200`), `instructions_list_chats` (`false`), `allow_sync` (`false`), `sync_max_seconds` и `auto_refresh_minutes`; `max_results` по умолчанию теперь `20`. `config set` принимает списки как `1,2`, `[1, 2]` или `1 2`.
- MCP отклоняет неизвестные аргументы с подсказкой «did you mean», принимает `chat_id` как алиас `chats` и подхватывает правки конфига без перезапуска.
- `tg-recall-mcp` завершается по EOF на stdin, при смерти supervising parent, по unused timeout (`TG_RECALL_MCP_UNUSED_TIMEOUT_SEC`, по умолчанию `600`) или idle timeout (`TG_RECALL_MCP_IDLE_TIMEOUT_SEC`, по умолчанию `1800`). Таймаут `0` отключает проверку; `TG_RECALL_MCP_PARENT_WATCHDOG=0` отключает parent reaping.
- Пересланные сообщения сохраняются с короткой меткой источника; `telegram check` запоминает id владельца, и в выводе для агента владелец показывается как `я`.
- Вывод `--json` компактный (без отступов), когда команду запускает AI-агент.

### Исправлено

- Вход в Telegram больше нигде не запрашивается, кроме `telegram auth`: `doctor`, `sync` и MCP сразу завершаются с понятной ошибкой, если сессии нет.
- Вывод CLI и MCP stdio всегда в UTF-8, независимо от кодовой страницы консоли Windows; MCP больше не отвечает на JSON-RPC notifications.
- Оболочки Claude Code и Codex (`CLAUDECODE`, `AI_AGENT`, `CODEX_*` без TTY) считаются автоматизацией, и к их вызовам CLI применяется политика доступа агентов.
- Токены оцениваются по классам символов (кириллица, латиница, цифры, эмодзи), а не как один токен на байт UTF-8, поэтому в тот же бюджет помещается примерно вдвое больше русского текста.

## v0.6.0 - 2026-08-04

- Добавлена постоянная ссылка без номера версии на инструкцию установки для Codex, Claude Code, Cursor и generic harnesses; она разрешает только проверенные wheel-файлы стабильного GitHub Release.
- Автоматизации разрешено безопасно проверять `integrate list`, `preview` и `status` без чтения профиля, архива и сессии, без сети и записи файлов harness; установка и обновление остаются только для человека.
- Добавлены типизированные настройки транскрипции в профиле и shell-free адаптер Faster-Whisper-XXL с проверкой локального executable и модели, настройками GPU, compute type и VAD, ограниченным timeout и безопасной диагностикой.
- `sidecar` остаётся способом транскрипции по умолчанию, а `auto` сначала обращается к Telegram; агенту по-прежнему нужна одна разрешённая явная `tg://` ссылка, и он не может менять конфигурацию.
- Добавлены полные русские версии основной публичной документации и синхронные EN/RU руководства по локальной транскрипции.
- Исправлено положение глобального флага `--json` в примерах; distribution tests гарантируют публикацию документации и исключение архивов, credentials, sessions, media, wiki и exports.

## v0.5.0 - 2026-08-03

- Усилено принудительное применение scope для агентов и MCP, сохранены монотонные watermarks синхронизации/backfill и возобновляемое восстановление `FLOOD_WAIT`.
- Добавлено транзакционное сопровождение архива через схему v6, диагностика `doctor`, фильтрованная инспекция jobs, явный retry и previews ремонта очереди.
- Добавлены маршрутизация контекста с бюджетами и guidance для Codex Spark/Luna, неизменяемые наборы evidence с цитатами, research sessions и локальная для профиля wiki memory.
- Добавлен опциональный полностью локальный гибридный поиск с явной конфигурацией embeddings, свежестью vector, детерминированными evidence с цитатами и keyword fallback.
- Добавлены ограниченные приватные AI export packs с проверяемыми manifests; архивы, сессии, медиафайлы, wiki, экспорты и packs остаются приватными по умолчанию.
- Добавлен opt-in синтез OpenAI Responses с проверками политики и локальным cited fallback, когда провайдер отключён или недоступен.
- Расширены совместимый CLI и read-only MCP surface при сохранении local-first границ приватности и JSON contracts.

## v0.2.0 - 2026-08-03

- Публичные CLI и пакет переименованы в `tg-recall`; сохранены устаревшие алиасы исполняемых файлов.
- Добавлены platform-aware roots, portable `--home` mode и изолированные профили Telegram.
- Новые медиафайлы сохраняются по относительным content-addressed keys вместо абсолютных путей файловой системы.
- Добавлены политики scope для media/transcription, `sync ensure`, обнаружение локального Whisper, команды agent guide/retrieve/export/materialize, безопасная legacy migration и согласованные backups.

## v0.1.0 - 2026-08-03

Первый публичный early-alpha релиз.

- Локальный архив SQLite, авторизация Telegram MTProto, scoped sync, очередь медиа, хранение транскриптов, FTS search и retrieval с цитатами.
- Поверхность операций CLI и локальный MCP server только для чтения.
- Усиление приватности на уровне пакета: строгий allowlist source distribution и тесты, отклоняющие непубличное содержимое релиза.

Известные ограничения документированы в [README.ru.md](README.ru.md).
