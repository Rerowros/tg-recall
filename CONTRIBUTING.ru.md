# Участие в разработке

[English](CONTRIBUTING.md) | **Русский**

## Локальная настройка

```powershell
uv sync --extra dev
uv run tg-recall --help
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv build
```

Используйте синтетические фикстуры из `tests/fixtures/`; никогда не добавляйте экспортированные чаты, реальные медиафайлы, учётные данные, файлы сессии или личные отчёты.

## Изменения

- Сохраняйте поведение CLI и MCP на общих примитивах хранения и получения данных.
- Сохраняйте цитаты `tg://chat/<chat_id>/message/<message_id>` для доказательств из архива.
- Добавляйте сфокусированные тесты для изменённого поведения.
- Обновляйте README и публичные ограничения, когда возможность неполная, ограничена или зависит от провайдера.
- Перед запросом ревью запускайте тест содержимого дистрибутива; исходные архивы должны содержать только публичный код и документацию.
- Перед ревью запустите `uv run ruff check .`, `uv run ruff format --check .` и `uv run pytest -q`.
- Внедрение форматирования идёт постепенно: проверка форматирования всего репозитория сообщает об устаревших файлах, пока не запланирован отдельный механический проход. Форматируйте каждый затронутый Python-файл с помощью `uv run ruff format <paths>` и не скрывайте оставшиеся файлы исключениями Ruff.

## Безопасность

Сообщайте о конфиденциальных уязвимостях через процесс в [SECURITY.ru.md](SECURITY.ru.md), а не в публичных issues.
