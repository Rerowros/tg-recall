# Политика безопасности

[English](SECURITY.md) | **Русский**

## Конфиденциальные данные

`tg-recall` обрабатывает файлы пользовательской сессии Telegram, API-учётные данные, локальные базы данных архива, скачанные медиафайлы и транскрипты. Считайте всё локальное состояние конфиденциальным.

Не включайте файлы сессии, данные архива, медиафайлы, транскрипты, реальные идентификаторы чатов или личные отчёты в issues, pull requests, логи, скриншоты или артефакты релиза.

## Граница автоматизированных агентов

`ai_access` определяет, что доступно AI-агентам: каждый вызов MCP и вызовы CLI из оболочки агента (`CLAUDECODE`, `AI_AGENT` или `CODEX_*` без TTY, `TG_RECALL_AI_MODE=1`, `CI`). Агенты видят только разрешённые чаты: `ai_access.allowed_chat_ids` или все чаты архива при `ai_access.allow_all_chats`. Запрошенные границы чатов, дат, медиа и результатов пересекаются с `ai_access`; пустое пересечение отклоняется до чтения строк архива или открытия клиента Telegram. Менять конфигурацию агенты не могут никогда.

| Автоматизированная операция | Политика |
| --- | --- |
| `chats`, `search`, `read` (MCP и CLI), `export` | Только разрешённые чаты, в пределах `allowed_since`, `allowed_until`, `allowed_media_types` и лимитов результатов; экспорты агентов остаются в каталоге `exports` профиля. |
| `sync` (MCP и CLI), автообновление перед `search` / `read` | Только при `ai_access.allow_sync=true` и только для разрешённых чатов. Читает Telegram и пишет только в локальный архив; ставить медиа в очередь агенты не могут. |
| `media materialize`, `transcribe run --citation` | Только CLI, для одной разрешённой ссылки `tg://` и разрешённого типа медиа. |
| `setup`, `telegram auth` / `check`, `chats --refresh`, `config`, `purge`, `backup`, `index`, `security`, `jobs`, `media usage` / `download`, `transcribe run` без `--citation` | Отклонено для агентов. |
| Отправка, редактирование или пометка сообщений прочитанными в Telegram | Не реализовано ни для кого. |

События allow/deny политики записывают только операцию и безопасные идентификаторы scope.
Они никогда не сохраняют исходный текст запроса, содержимое сообщений, учётные данные или данные сессии.

## Сообщение об уязвимости

Для уязвимости, которая может раскрыть локальные данные архива, материал сессии, учётные данные или позволить непреднамеренные действия Telegram, используйте приватное сообщение об уязвимости GitHub для этого репозитория. Не открывайте публичный issue с данными воспроизведения, содержащими секреты или личный контент.

Укажите затронутую версию, минимальное санитизированное воспроизведение, воздействие и, если возможно, идеи по устранению.

## Оперативные действия

Если сессия Telegram могла быть раскрыта, отзовите её в Telegram Settings -> Devices, удалите затронутый локальный файл сессии и авторизуйтесь повторно. Прежде чем считать раскрытие локализованным, проверьте публичную историю Git и артефакты релизов.
