# Roadmap

[English](ROADMAP.md) | **Русский**

`v0.5.0` — текущая выпущенная базовая версия. Она включает profile-aware локальный архив и portable mode из `v0.2.0`, а также усиленную безопасность агентов и синхронизации, сопровождение схемы v6, маршрутизацию контекста агентов с бюджетами, приватную wiki/evidence/research memory, локальный гибридный поиск, приватные packs и opt-in ответы LLM с учётом политики.

Выпущенные ниже этапы сохраняют историю своих версий. Будущая работа остаётся упорядоченной по зависимостям и риску, а не по календарным датам, и сохраняет совместимость существующих контрактов CLI и JSON, если будущее изменение OpenSpec явно не объявит иное.

## Принципы продукта

- Local-first по умолчанию: архив, учётные данные, сессии, медиафайлы, wiki и экспорты остаются в пределах выбранного приватного профиля.
- Явный scope: без неявной синхронизации всего архива, скачивания медиа, транскрибации, экспорта или загрузки провайдеру.
- Безопасная граница агентов: агенты могут читать, синхронизировать, materialize медиа и транскрибировать в пределах одобренного пользователем scope; они не могут авторизовать Telegram, изменять учётные данные/config, удалять данные или отправлять сообщения.
- Доказательства до синтеза: каждый производный результат сохраняет стабильные цитаты `tg://` и может быть развёрнут обратно в контекст исходника.
- Опциональный интеллект: embeddings и LLM-провайдеры являются opt-in дополнениями; keyword retrieval и extractive ответы остаются доступными без них.

## Выпущенный этап 1 — v0.2.x безопасность и корректность синхронизации

OpenSpec: `harden-agent-safety-and-sync`

- Применяет единую политику чтения агентами в CLI и MCP, включая инструменты только для метаданных, лимиты результатов и границы чата/даты/медиа.
- Сохраняет watermark при пустых incremental или backfill запусках и поддерживает монотонное и возобновляемое состояние forward/backfill.
- Включает регрессионные тесты для запрещённых команд агента, scoped reads, no-op sync, `FLOOD_WAIT` и стабильных JSON-ошибок.

Результат: автоматизированный агент не может расширить доступ к архиву или вызвать запрещённые операции, а повторная/no-op синхронизация не может потерять прогресс.

## Выпущенный этап 2 — v0.2.x сопровождение архива

OpenSpec: `add-archive-maintenance-controls`

- Вводит явные упорядоченные миграции SQLite через схему v6 с проверками версии, транзакционным откатом и диагностикой `doctor`.
- Добавляет фильтрованную инспекцию jobs вместе с явным retry, repair и восстановлением stale jobs без молчаливого повтора постоянных сбоев.
- Единообразно применяет каждый заявленный фильтр к keyword, transcript, token-overlap и semantic retrieval.
- Включает детерминированные машиночитаемые отчёты для операций сопровождения.

Результат: обновления восстанавливаемы, сбои очереди диагностируемы и исправляемы, а все режимы поиска соблюдают один контракт фильтрации.

## Выпущенный этап 3 — v0.3.0 контекст агентов и оркестрация знаний

OpenSpec: `optimize-agent-context-and-memory-routing`

- Использует progressive retrieval с явными бюджетами items, context, tokens, stages, retries и tool calls вместо повторной отправки больших окон чата.
- Сохраняет неизменяемые наборы доказательств с цитатами и компактные research checkpoints, чтобы новый AI turn или Codex chat мог продолжить прошлую работу без повторного поиска тех же сообщений.
- Предоставляет единый profile-aware каталог поверх raw messages/transcripts, wiki knowledge и сохранённых evidence, сохраняя raw Telegram records авторитетными.
- Генерирует версионированный Codex prompt, который предпочитает доступную `gpt-5.3-codex-spark` для почти мгновенного узкого read-only retrieval с использованием её отдельного лимита Codex, а `gpt-5.6-luna` использует как стабильный недорогой fallback.
- Измеряет citations, quality, calls/turns, estimated и actual tokens, когда доступны, latency, cache reuse и стоимость на успешную задачу.

Результат: повторная работа может переиспользовать актуальные evidence, старые выводы могут разворачиваться к исходным сообщениям, а недорогая маршрутизация снижает измеренное потребление без потери требуемых доказательств или границ приватности.

## Выпущенный этап 4 — v0.3.x приватная wiki memory агентов

OpenSpec: `add-private-agent-wiki-memory`

```text
raw Telegram deltas -> immutable cited snapshots -> versioned Markdown wiki -> compact agent lookup
```

- Добавляет profile-aware метаданные snapshot, revision, assertion и citation.
- Компилирует только новые source deltas в страницы для людей, отношений, проектов, решений и стилей общения.
- Разделяет observations и hypotheses и сохраняет confidence, freshness, историю revisions и source citations.
- Добавляет компактный lookup и разворачивание raw-source через безопасные интерфейсы CLI и read-only MCP.

Результат: ответ wiki может сообщить freshness и развернуть каждое assertion до исходного доказательства Telegram. Данные wiki остаются локальными и исключены из Git и артефактов релиза.

## Выпущенный этап 5 — v0.4.0 локальный гибридный поиск

OpenSpec: `add-local-hybrid-retrieval`

- Добавляет явный локальный embedding provider и версионированный vector index наряду с устаревшим путём token-overlap.
- Объединяет FTS, metadata filters, transcript matches и vector similarity с детерминированным ранжированием и дедуплицированными evidence windows.
- Оставляет token/keyword fallback доступным, когда embeddings отключены, недоступны или устарели.
- Показывает index provenance, freshness, rebuild status и bounded batch retrieval для агентов.

Результат: semantic retrieval работает полностью офлайн, когда настроен, никогда не ослабляет принудительное применение scope и безопасно деградирует к текущему локальному поиску.

## Выпущенный этап 6 — v0.4.x приватные AI export packs

OpenSpec: `add-private-ai-export-packs`

- Экспортирует bounded, profile-aware packs из raw evidence и/или synthesized wiki pages для downstream AI tools.
- Включает manifests со scope, provenance, citations, freshness, schema version и content hashes.
- По умолчанию записывает только в приватный каталог exports профиля; внешние пути требуют явного выбора пользователя.
- Поддерживает incremental regeneration без дублирования неизменённого контента.

Результат: экспорт переносим и проверяем, не содержит учётных данных, сессий, абсолютных приватных путей или данных за пределами заявленного scope.

## Выпущенный этап 7 — v0.5.0 LLM-ответы с учётом политики

OpenSpec: `add-policy-aware-llm-answers`

- Добавляет границу адаптера провайдера для `ask`, сохраняя `extractive` провайдером по умолчанию.
- Отправляет только bounded retrieved evidence после явных проверок политики провайдера и scope.
- Записывает provider/model, evidence citations, решение политики, использование токенов и санитизированные метаданные сбоев в локальный audit trail.
- Сохраняет детерминированные JSON contracts и возвращает cited evidence, когда провайдер отключён или недоступен.

Результат: ни один провайдер не получает неявно данные всего архива, каждый синтезированный ответ ссылается на свои доказательства, а сбой провайдера не блокирует локальное получение данных.

## Гигиена релизов и OpenSpec

- Перечисленные базовые изменения OpenSpec завершены и остаются неархивированными для аудита релизов.
- Будущие этапы должны использовать отдельную implementation branch и архивировать своё изменение OpenSpec только после сфокусированных тестов, полного `pytest`, проверок приватности дистрибутива и прохода документации.
- Считайте блокерами релиза регрессии приватности, деструктивный доступ агента, потерю цитат и несовместимость восстановления.
